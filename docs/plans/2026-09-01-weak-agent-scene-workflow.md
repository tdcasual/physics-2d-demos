# 2026-09-01 弱代理场景工作流加固

> 状态：已执行。归档记录，不作为现行方案。

> 来源：需求分析——让 OpenClaw 等弱编程代理能可靠新增场景。设计原则：
> 规范的价值 = 机器强制力 × 报错指引性，文档只做索引。

## 方案要点

- 弱代理的核心死因是反馈回路断裂（8+ 条命令必然漏跑），故 P0 全部
  围绕「单命令验证 + 处方式报错 + 执行卡」。
- 脚手架必须自证明，否则模板与门禁会悄悄脱节（实践中首跑即抓到
  canvas 可选性类型 bug）。
- 防钻靠 CODEOWNERS + CI 分诊，不靠代理自觉。
